# 게임 카드 레이아웃 동일 적용 규칙

## 규칙

아래 "동일 그룹" 목록에 속한 화면은 전부 같은 "게임 카드"를 보여준다. **하나의 카드 레이아웃(구조, 클래스, 스타일)을 수정하면, 사용자가 그 자리에서 명시적으로 "이건 다르게 해줘"라고 지정하지 않는 한 — 즉 사용자가 별도로 말하기 전까지는 항상 — 목록의 나머지 전부에도 동일하게 적용한다.**

- 사용자에게 "다른 곳에도 적용할까요?"라고 되묻지 않는다 — 무조건 전부 동일하게 반영한다.
- 새로 게임 카드를 보여주는 화면을 추가하는 경우, 이 문서의 목록에도 추가한다.
- 기준(원본)은 `/betazone` (`BetazonePage.tsx`)의 카드다. 다른 위치를 수정할 때는 이 카드의 구조를 기준으로 맞춘다.
- 두 파일의 `GameCard`/`LiveGameCard` 함수는 함수명만 다르고 나머지는 **완전히 동일한 코드**여야 한다 (2026-08-26 기준 diff로 확인 완료) — **단, 2026-09-15부터 예외 발생, 아래 "2026-09-15 예외" 항목 참고.** 한쪽만 고치고 다른 쪽을 잊는 실수를 막기 위해, 수정 후에는 두 함수 본문이 여전히 동일한지 diff로 확인하는 습관을 들인다(단, 아래 예외로 명시된 베타 전용 블록은 diff 대상에서 제외).

### 2026-09-15 예외 — 베타존 카드 2·3번째 줄은 라이브게임과 다르다

베타존 카드의 제목 아래 2줄(테스트 시작/진행/종료 상태, 마감임박 배지)과 3줄(참여 인원/목표 인원 + 참가하기·모집완료 버튼)은 **베타 테스트 모집이라는 베타존만의 개념**(시작일/종료일, `testers`/`maxTesters`, 선착순 모집)이라 라이브게임에는 애초에 대응 개념이 없다. 그래서 이 변경은 `BetazonePage.tsx`에만 적용했고 `LiveGamesPage.tsx`는 건드리지 않았다 — "동일 그룹 자동 적용" 원칙의 예외([[feedback_beta_only_pause_live_sync]]와 같은 맥락: 베타 전용 개념은 라이브에 억지로 맞추지 않는다). 썸네일/카드 틀(테두리·둥근모서리·크기)은 여전히 동일 유지.

- 2번째 줄(제목 아래): 설명(`game.description`) 대신 테스트 단계 텍스트 — 시작 전 `"{formatDate(startDate)} 테스트 시작"`, 진행 중 `"테스트 중"`, 종료 `"테스트 종료"` (판정 함수 `getBetaPhase()`, 종료일 지남=ended, 시작일 지남=active, 그 전=before)
- 3번째 줄(카드 하단): 별점/장르 대신 `참여 N/M명` + 버튼(시작 전에만 노출: 정원 미달 "참가하기", 정원 도달 "모집 완료" — 진행 중/종료에는 버튼 자체가 없음)
- 마감임박 배지: 시작 전 단계에서만, 정원 10명 이하 남았을 때 썸네일 좌상단에 표시(스타일은 `MainPage.tsx`의 `BetaZoneRecommendRow`와 동일하게 맞춤)
- 테스트 종료(`ended`) 카드는 클릭해도 상세 페이지로 이동하지 않고(호버 테두리 강조도 없음), 썸네일이 흐리게(`grayscale opacity-60`) 처리되며, 목록 정렬에서 항상 맨 뒤로 밀린다(`sortedGames`, 필터/정렬 조건과 무관하게 종료된 게임만 뒤로 재배치)
- 별점(`StarRating`)/장르 텍스트는 베타존 카드에서 완전히 제거됨(라이브게임 카드에는 그대로 남아있음 — `docs/rating-consistency-rule.md`의 라이브게임 항목은 유효)

### 현재 카드 구성 (2026-09-02 갱신)

여러 차례 요청으로 계속 단순화되어 왔다 — 새로 뭔가 추가/복원할 때는 최신 상태인 이 목록을 기준으로 판단한다.

- 썸네일 이미지 (`aspect-[5/5]`(정사각형), `object-cover`, 호버 시 확대 — 2026-09-02 "5:5로 넣어봐" 요청으로 기존 `aspect-[39/20]`에서 변경)
- 제목 (`truncate`, 1줄, `text-[18.2px]` — 2026-09-02 "30% 키워" 요청으로 기존 `text-sm`(14px)에서 확대)
- 설명 (줄 수 제한 없이 전체 텍스트 표시 — 2026-09-02, "한 줄로 줄여" 요청 후 바로 "그냥 다 나오게 해" 요청으로 되돌림. `line-clamp`/`min-h` 전부 제거. 제목과의 간격 `mt-[2.4px]`(기존 `mt-0.5`에서 20% 확대), 왼쪽으로 살짝 들여쓰기 `pl-1`)
- 카드 높이 통일: 그리드(`grid`)의 기본 `align-items: stretch`를 활용 — 카드 루트 `div`에 `h-full`, 내부 테두리 박스에 `h-full flex flex-col`, 텍스트 영역에 `flex-1`을 줘서 **한 행(row) 안에서 설명이 가장 긴 카드 높이에 나머지가 자동으로 맞춰짐** (하드코딩된 고정 높이가 아니라 그때그때 가장 큰 카드 기준, 2026-09-02)
- 위 세 가지가 **하나의 테두리 안에** 통합된 단일 카드 (`border-2 border-gray-300 dark:border-gray-600`, `rounded-2xl`) — 이미지와 텍스트가 분리된 두 블록이 아니라 한 장의 카드
- 평점: 공용 컴포넌트 `StarRating`(`apps/web/src/components/StarRating.tsx`, `size={3.5}`) + 숫자(`(game.rating || 0).toFixed(1)`, `text-yellow-400 font-bold text-xs`) — 2026-09-02 "평점이랑 장르 다시 넣어" 요청으로 복원, 이후 "평점 디자인이랑 칼라 통일" 요청으로 사이드바 별점과 같은 공용 컴포넌트로 교체 (자세한 내용은 `docs/rating-consistency-rule.md` 참고)
- 장르: 평점 아래, 배지(Badge)가 아니라 순수 텍스트로 `game.genre` 표시 (`text-xs text-accent`, 없으면 미표시) — 2026-09-02 "배찌로 하지말고 텍스트로" 요청으로 배지 대신 텍스트로 변경
- 평점/장르 위치 고정: 제목+설명을 담는 블록과 평점/장르 블록을 분리하고, 텍스트 영역 전체(`p-2 flex-1 flex flex-col`)에서 평점/장르 블록에 `mt-auto`를 줘서 **설명 줄 수가 카드마다 달라도 평점/장르는 항상 카드 하단 동일한 위치**에 정렬됨 (2026-09-02, "설명 줄이 달라도 평점이랑 장르는 동일한 위치에" 요청)
- 평점/장르 블록도 설명과 동일하게 `pl-1`로 오른쪽 들여쓰기 (2026-09-02, "평점이랑 장르도 설명 행 위치만큼 오른쪽으로 이동" 요청)
- 카드 폭/간격: 그리드 컨테이너의 가로 간격 `gap-x-6`(24px) → `gap-x-[122px]` — 카드 개수(4열)와 컨테이너 폭은 그대로 두고 간격만 넓혀서 결과적으로 카드 폭이 정확히 25% 줄어듦(294px → 220.5px, 2026-09-02 xl 4열 기준 실측). 세로 간격(`gap-y-[28px]`)은 변경 없음
- 2026-09-15, "간격 30% 좁혀" 요청 → 처음엔 그리드 전체를 `xl:max-w-[70%]`로 줄였다가("카드 폭도 같이 줄었지?" 확인 질문에 그렇다고 답했더니) "카드 폭은 그대로 두고 간격만 줄이라"는 정정을 받음. `gap-x-[122px]` → `gap-x-[85px]`(간격만 30% 축소) + `xl:max-w-[91%] xl:mx-auto`로 카드 폭은 유지(그리드 `fr` 트랙 특성상 간격이 줄면 카드가 그만큼 넓어지므로, 줄어든 간격 총량만큼 컨테이너 폭도 같이 줄여서 상쇄).
- 2026-09-15, 곧바로 "카드 크기 20% 줄여봐" 요청 → 이번엔 진짜로 카드 폭 자체를 줄이는 것. 간격(`gap-x-[85px]`)은 그대로 두고, 컨테이너 `xl:max-w-[91%]` → `xl:max-w-[77%]`로 축소해 카드 폭만 20% 감소(xl 4열 기준: 220.5px → 176.4px). `xl:` 접두사로 데스크톱 4열 레이아웃에서만 적용, 모바일/태블릿(1~3열)은 그대로 둠. 두 파일(`BetazonePage.tsx`/`LiveGamesPage.tsx`) 동일 반영.
- **"플레이 중인 게임" 줄 아이콘 폭은 게임 카드 그리드와 동일한 CSS `calc()` 공식으로 계산함(하드코딩 px 아님)** — 처음엔 `PLAYED_ICON_WIDTH` 상수(176px 고정값)로 했다가 실제 화면과 안 맞았고, 그 다음 `ResizeObserver`로 첫 카드를 실측하는 방식도 시도했지만 역시 어긋났다(마운트 타이밍 등으로 신뢰 불가). **최종**: 그리드와 동일하게 `xl:max-w-[77%] xl:mx-auto`로 감싼 뒤, 각 아이콘 폭을 `xl:w-[calc((100%_-_255px)/4)]`(255px = 간격 85px × 3칸, 4열; 언더스코어는 Tailwind 임의값 안 공백 표기 — CSS `calc()`의 `-` 연산자는 양옆 공백이 필수라 생략하면 무효한 값이 됨)로 지정 — 그리드가 4열을 나누는 계산식을 그대로 복제한 것이라 항상 정확히 일치함. **카드 그리드의 폭 제한 비율(`77%`)·간격(`85px`)·열 수(4)를 바꾸면 이 calc식의 숫자도 반드시 같이 바꿔야 함** — 자동으로 따라가지 않는다(JS 실측 방식이 아니라 순수 CSS 공식이므로).

**제거된 것들 (요청에 따라 순차적으로 삭제됨, 함부로 복원하지 않는다)**: 찜하기(하트) 버튼, 플레이 수, GRAC 등급 배지, 가격 표시, accent 컬러 테두리/배경. "컬러는 따로 넣지 말고" 요청이 있었으므로 카드 틀 자체는 브랜드 컬러 강조 없이 중립(회색) 톤 유지 (단, 장르 배지 색상은 예외로 accent 사용). 별점·장르는 2026-09-02 재요청으로 복원되었으므로 이 제거 목록에서 제외.

## 참고: 카드 레이아웃 외 필터 기능도 동일 그룹 적용 대상

- 이 문서는 "카드 레이아웃"에 초점을 맞추고 있지만, 라이브존/베타존은 **필터 바(장르 태그, "내 게임" 태그 등)도 항상 동일하게 유지**한다. 2026-08-27, 라이브존에만 "내 게임" 필터 태그를 추가했다가 "둘 다 동시에 하라고 했잖아" 지적을 받고 베타존에도 동일 반영함 — 관련 메모리 [[feedback_betazone_livegame_card_sync]].
- "내 게임" 태그의 판정 기준/동작 규칙은 `docs/platform-rules.md` 1.8절 참고.
- **2026-09-15**: "태그 없애봐, UI에서만 없애는거야" 요청으로 장르 태그(전체/RPG/액션/.../기타)·"내 게임" 태그 버튼의 **렌더링만** 두 파일에서 제거함 — `selectedGenre`/`myGamesOnly` 상태, `handleSelectGenre`/`handleToggleMyGames` 핸들러, `loadGames`의 `genre`/`ids` 파라미터 로직은 전부 그대로 남아있다(코드/기능 삭제 아님, 화면에만 안 보이는 상태). 나중에 다시 보이게 할 땐 지워진 JSX 블록만 복원하면 됨.
- 같은 요청 직후 "검색 입력창을 서브타이틀과 같은 줄로 올려" 요청으로 검색창을 기존 "Filters" 줄에서 헤더 섹션 안으로 이동. 처음엔 부제를 `flex` 행으로 바꿔 검색창과 나란히 뒀다가, "설명은 원래 자리에 둬야지"라는 정정을 받고 **최종 구조**로 변경: 제목+부제 블록(`text-center`)은 원래 그대로 중앙 정렬 유지, 검색창은 헤더 섹션(`relative`)에 `absolute right-4 bottom-0`으로 부제와 같은 높이(하단)·오른쪽에 겹쳐서 배치(`md:` 이상에서만, 모바일은 헤더 아래 별도 줄로 폴백). 부제 위치/정렬 자체는 손대지 않는 게 핵심.
- **2026-09-15, "플레이 중인 게임" 줄 추가** (구분선과 게임 카드 그리드 사이, `PlayedGamesRow` 컴포넌트, 두 파일 동일) — 로그인 유저의 최근 플레이 게임을 한 줄로, 최신순 왼쪽부터 배치. 각 존 전용 데이터(베타존은 `serviceType=beta`만, 라이브존은 `serviceType=live`만 — 백엔드 `getMyRecentGames`가 존별로 필터링)만 노출된다.
  - 처음엔 아이콘을 카드보다 2.3배 작게(77px, 고정 `height` 인라인 스타일) 만들었는데 이미지가 깨지는 버그가 있었고, 사용자가 "이상하다 빼"라며 기능 자체를 없앴다가, 곧바로 "다시 살리되 아이콘 폭은 게임 카드 폭에 맞추라"고 재요청함.
  - 카드와 동일한 `aspect-[5/5]` 방식으로 바꿔서(`GameCard`의 썸네일과 완전히 같은 마크업 패턴) 이미지 깨짐 버그를 해결함 — 작은 `height`를 인라인으로 고정한 게 원인이었던 것으로 보임, 새로 만들 때도 이 패턴(고정 height 지정 금지, `aspect-[5/5]`만 사용)을 따를 것.
  - 아이콘 폭 맞추기는 하드코딩(176px) → `ResizeObserver` 실측 → 최종 `calc()` 공식까지 세 번 시도 끝에 정착함. 자세한 내용은 위 "카드 폭/간격" 항목 참고.
  - 하단엔 제목만 표시(설명/장르/평점 없음), 가로 스크롤은 마우스 드래그로만(스크롤바 숨김).
  - **2026-09-15, "제목 오른쪽 구분선 삭제, 아이콘 60%→20% 크기 조정" 요청** — 제목 옆 `flex-1 h-px bg-line` 구분선 제거, 아이콘 폭을 순차 조정(`w-[176px]`→`w-[70.4px]`(60% 축소)→`w-[84.5px]`(다시 20% 확대), xl calc 배율도 `*0.4`→`*0.48`로 동일 반영).
  - **2026-09-15, 이미지 화질 저하 원인 수정** — 아이콘 축소 후 화질이 깨져 보인다는 지적으로 원인 확인, `next/image`의 `unoptimized` 속성이 서버 리사이즈를 꺼버려 브라우저가 원본 고해상도 이미지를 그대로 축소 렌더링한 게 원인이었음. `next.config.ts`에 `/uploads/**` remotePatterns가 이미 허용돼 있어 안전하게 `unoptimized` 제거 + `sizes="90px"` 추가로 해결(두 파일 동일 반영). 단, 재사용한 기존 썸네일 파일 자체의 원본 해상도가 제각각이라(정사각 저해상도 vs 와이드 고해상도를 강제 정사각 크롭) 일부는 여전히 흐릿하게 보일 수 있음 — 이건 코드 문제가 아니라 원본 파일 품질 차이.
  - **2026-09-15, "플레이 중인 게임" 줄과 게임 카드 그리드는 항상 같은 폭 유지 (사용자가 명시적으로 재확인, "다르게 이야기하기 전까지")** — 처음엔 제목 줄에 폭 제한(`xl:max-w-[77%] xl:mx-auto`)이 안 걸려 있어서 그리드보다 제목이 왼쪽으로 더 나가 보이는 버그가 있었음(1차 수정: 제목 줄에도 동일 클래스 추가). 이후 "플레이 중인 게임 줄 넓이랑 아래 게임 그리드 넓이랑 다르다"는 재지적을 받고, **각자 따로 `xl:max-w-[77%] xl:mx-auto`를 중복 선언하던 구조를 버리고, `PlayedGamesRow`와 게임 그리드를 감싸는 공유 래퍼 div 하나에만 이 클래스를 주도록 리팩터링**(두 파일 동일). 폭 제한이 두 곳에 따로 있으면 한쪽만 수정했을 때 다시 어긋날 수 있어서, 구조적으로 항상 같은 폭이 되도록 만든 것 — 앞으로 이 폭 값(`77%`)을 바꿀 때도 이 공유 래퍼 한 곳만 수정하면 됨.
  - **2026-09-15, "플레이 중인 게임" 줄의 아이콘을 서브아이콘(`Game.subIcon`, 320×144px)로 교체 + 박스도 와이드하게** — 새로 생긴 `subIcon` 필드(자세한 내용은 `docs/image-upload-size-consistency-rule.md`) 도입으로, 이 줄의 박스가 `aspect-[5/5]`(정사각) → `aspect-[20/9]`(와이드)로 바뀌고 이미지도 `g.thumbnail` → `g.subIcon`로 바뀜(값 없으면 PLACEHOLDER). 폭(`w-[109.85px] xl:w-[calc(...)]`)은 그대로 유지, 높이만 종횡비에 따라 줄어듦. 같은 이유로 헤더 검색 드롭다운 썸네일(`w-10 h-10`→`w-14 aspect-[20/9]`)과 `PlayerGameDetailPage.tsx`의 "개발사" 카드 아이콘(`w-11 h-11`→`w-20 aspect-[20/9]`)도 동시에 전환함 — 이 3곳은 더 이상 이 문서의 "정사각형 아이콘" 그룹이 아니라 서브아이콘 전용 표시 위치임에 유의.

## 이 그룹에서 제외되는 것 (의도적 제외)

- `apps/web/src/components/pages/GameListPage.tsx` — 게임 카드 구조 자체는 동일하지만 앱 라우터에 연결되어 있지 않은(사용되지 않는) 페이지라 그룹 대상에서 제외. 실제로 라우팅에 연결되면 그룹에 편입하고 이 문서도 업데이트한다.
- 메인 화면(`MainPage.tsx`)의 게임 카드 — 홈 화면 전용으로 의도적으로 더 단순화된 다른 스타일이며, 이 그룹의 "탐색/목록" 카드와는 성격이 다르다.
