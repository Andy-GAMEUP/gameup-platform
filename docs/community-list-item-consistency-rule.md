# 커뮤니티 리스트 아이템 동일 적용 규칙

## 규칙

커뮤니티(`/community`)에서 글/공지를 "리스트 행"으로 보여주는 곳은 전부 **탭/화면 구분 없이 하나의 동일 그룹**이다. 이 중 한 곳의 리스트 아이템(행) 내용 구성 — 제목 크기/굵기/색상, 닉네임 크기/색상, 뱃지 유무, 통계 배치 등 — 을 수정하면, 사용자가 명시적으로 "이 화면만 다르게 바꿔라"라고 하지 않는 한 **묻지 않고 같은 그룹 나머지 전부에 동일하게 적용**한다.

**틀(컨테이너/카드 스타일)은 사용자가 명시적으로 지정했을 때만 바꾼다.** 기본적으로는 각 위치마다 원래 모습 그대로 유지 — 묻지 않고 자동으로 통일하는 대상이 아니다. (2026-08-13, 유저 게시물 리스트 틀을 공지 박스처럼 바꿨다가 "틀은 내가 만지라고 안 했다, 콘텐츠만 통일하라 그랬다"고 되돌림 받은 적 있음.) 다만 나중에 사용자가 "게시글 리스트를 한 카드로 묶어줘"라고 명시적으로 요청해서, **소형(리스트) 뷰(`viewMode==='small'`)는 공지 박스와 동일하게 구분선 있는 하나의 박스**로 통일했고(2026-08-13), **대형 카드(`viewMode==='large'`)는 "각 카드 형태는 하나 박스에 넣을 필요 없이 이대로 유지"라고 명시해서 개별 카드 그리드 그대로 유지**했다(2026-08-13). 새 화면을 추가할 때 틀을 어떻게 할지는 사용자에게 물어보고, 답이 없으면 그 리스트가 속한 그룹의 최근 확정 사례를 따른다.

## 그룹 전체에 공통 적용 (제목/닉네임 — 위치·틀과 무관하게 전부 동일)

- **제목**: `text-[14.72px] font-medium text-text-primary` (2026-08-14, 기존 `text-[18.4px] font-semibold`에서 크기 20%↓ + 굵기 한 단계↓(semibold→medium)로 변경. 그 전엔 16px→18.4px로 15% 확대했었음, 2026-08-13)
- **제목 마우스오버 색상**: 제목에 `group-hover:text-accent transition-colors`를 추가하고, 그 제목을 감싸는 클릭 가능한 요소(`<Link>`/`<li onClick>`/카드 `<div onClick>`)에 `group` 클래스를 반드시 같이 붙인다 — 부모에 `group`이 없으면 `group-hover:*`가 동작하지 않는다. (2026-08-14, 11곳 중 4곳만 있고 7곳은 빠져있어서 전부 통일함 — 새 리스트 화면을 추가할 때 이 두 개를 항상 짝으로 붙일 것.)
- **닉네임/작성자 (및 동일 역할 요소 — "게임업 관리자", 개발사 담당자 이름, "알 수 없는 개발사" 포함)**: `text-[13.2px] text-text-secondary` (기존 12px+muted 상속에서 10% 확대 + 더 어두운 색으로 변경, 2026-08-13)

- 홈 탭 "공지사항" 카드
- 홈 탭 "게임 공지" 카드 (2026-08-18에 "게임별 공지사항"에서 텍스트만 변경)

- 공지사항 > 게임 공지 탭 (전체 게임 공지)
- 게임 선택 시 "{게임명} 공지사항" 목록

**홈 탭 "게임 공지" 카드 레이아웃 예외 (2026-08-18)**: "게시물 3개씩 잘 보이게, 4줄 보이게 해봐" 요청으로 세로 리스트(`<ul><li>`)에서 **3열 그리드**로 바꿈 — `grid grid-cols-3 gap-3 p-4`로 12개(`gameNotices.slice(0, 12)`, 4줄×3열)까지 보여준다. 처음엔 `renderNoticeLargeCard`(썸네일 위에 큰 이미지가 오는 대형 카드)를 재사용했는데, 바로 이어서 "게시물은 소형으로 해봐"라고 정정받아 **그룹 A의 소형(리스트) 뷰 스펙**(52x52 썸네일 좌측 + 1줄: 제목+뱃지+날짜 / 2줄: 작성자+조회수+좋아요, "공지사항 > 게임 공지 탭"의 리스트뷰와 동일 구성)으로 바꾸고, 각 항목을 `border border-line rounded-lg`로 감싸 그리드 셀 경계를 표시함(원래 세로 리스트는 `border-t` 구분선이었는데 그리드라 셀마다 테두리가 필요해짐). 다른 곳(공지사항 탭)은 리스트/대형 카드 토글 그대로 — 이건 이 홈 위젯 하나만의 레이아웃 예외(3열 그리드 + 소형 콘텐츠 조합).
- **이 위젯만의 추가 예외 — 작성자 자리**: 그룹 A의 나머지 전부는 "작성자" 자리에 개발사 담당자 이름(`n.developer?.username`)을 쓰는데(2026-08-14에 확정된 그룹 전체 규칙, 위 참고), **이 홈 위젯만** "게시물 작성자는 해당 게임 탭 이름으로 변경" 요청으로 `n.game?.title`(게임 이름)을 대신 보여준다 — 클릭 기능은 없음(순수 텍스트, 예전에 있었던 "게임 이름 버튼" 방식으로 되돌린 게 아니라 그냥 텍스트만 게임명으로). 다른 game notice 위치(게임 공지 탭, 게임 선택 시 목록 등)는 여전히 개발사 이름 그대로 — 이 필드는 위치마다 다를 수 있는 유일한 예외 항목이니 나중에 "왜 여기만 게임명이지?"라는 질문이 나오면 이 항목을 참고할 것.

구성: 1줄 = 제목 + 타입 뱃지(공용 `NoticeTypeBadge` 컴포넌트, `docs/badge-consistency-rule.md` 참고) + (spacer) + 날짜 / 2줄 = 작성자("게임업 관리자" 고정 텍스트, 또는 게임 공지의 경우 담당 개발자 이름) + 조회수 + 좋아요 (2개 스탯). **댓글수는 없음** — 공지는 댓글 기능 자체가 없어서 댓글 카운팅 UI를 아예 넣지 않는다(2026-08-13, 이전엔 하드코딩된 `0`으로 표시했었는데 제거함).

**2026-08-14 업데이트**: 게임 공지 2줄의 작성자 자리는 원래 "게임 이름 버튼"(클릭 시 해당 게임으로 이동)이었는데, 사용자가 "닉네임 자리에 게임명 대신 개발사 이름 넣어"라고 요청해서 **게임을 등록한 개발자의 계정 이름(`developerId.username`)**을 보여주는 순수 텍스트로 변경(클릭 이동 기능 없음). 게임 선택/이동은 이제 이 자리가 아니라 각 화면의 다른 요소(상세페이지의 "게임 바로가기" 배지 등)로만 가능. 백엔드에서 `GameAnnouncement` 조회 시 `gameId`뿐 아니라 `developerId`도 함께 join해서 `developer: {_id, username}` 필드로 내려준다 (`getRecentGameAnnouncements`, `getPublicGameAnnouncements`, `getGameAnnouncementById` 전부).

**썸네일 이미지 (2026-08-13 업데이트, 같은 날 두 번째 수정으로 최종 확정)**: 공지 종류 둘 다 이제 게시물(Post)과 동일하게 **작성자가 직접 첨부한 이미지**를 썸네일로 우선 사용한다.
- **플랫폼 공지("게임업 공지")**: `Announcement` 모델에 `images`/`thumbnailIndex` 추가(관리자 공지 작성 폼에 업로드+썸네일 선택 UI). 이미지가 없으면 Post처럼 **썸네일 자리 자체가 생기지 않음**(플레이스홀더 없음) — 게임이 연결되어 있지 않으므로 대체할 아이콘 자체가 없음.
- **게임 공지**: `GameAnnouncement` 모델에도 `images`/`thumbnailIndex` 추가(게임 관리 페이지의 "새 공지사항 작성" 모달에 업로드+썸네일 선택 UI, `gameService.uploadAnnouncementImages` 재사용 — 에디터로 본문에 이미지를 삽입해도 자동으로 이 썸네일 후보 목록에 들어감, Post의 `uploadedImages` 패턴과 동일). 목록에서는 **자기 자신의 첨부 이미지가 있을 때만 그 이미지를 보여주고, 없으면 Post처럼 썸네일 자리 자체가 안 생김** — 게임 자체 썸네일이나 `Gamepad` 아이콘으로 폴백하지 않는다(2026-08-13, 세 번째 수정으로 최종 확정). 처음엔 "이미지 없으면 게임 썸네일/아이콘으로 폴백"이었는데, 사용자가 "이미지 안 넣은건 게시물이랑 동일하게 썸네일 이미지 안나오게 해"라고 명시적으로 정정함.

이 기능 추가는 "내가 통일하랬지? 통일해 게시물이랑 똑같이 게임업 공지도 동일하다"는 요청에서 시작해서, 게임 공지까지 같은 기준으로 확장됨. **정리**: 공지(게임업 공지/게임 공지) 둘 다 이제 Post와 완전히 동일한 규칙 — 첨부 이미지 있으면 보여주고, 없으면 썸네일 자리 자체가 없음. 게임 아이콘을 보여주는 로직은 완전히 제거됨.

**고정(`Pin`) 표시 전면 제거** (2026-08-13): 커뮤니티 게시물(Post)에는 `isPinned`를 실제로 설정할 수 있는 기능(관리 UI)이 아예 없어서 — "커뮤니티 전체적으로 고정 기능 없잖아" — 리스트/상세 페이지 어디에도 고정 뱃지·아이콘·테두리색 구분을 넣지 않는다. 플랫폼 공지(Announcement)는 관리자 페이지(`AdminCommunityPage.tsx`)에 실제 고정 토글 기능이 있지만, 그것과 별개로 사용자 화면(공지 리스트/상세)에서는 고정 뱃지를 표시하지 않기로 함(2026-08-13, 상세 페이지의 "고정" 뱃지도 명시적으로 빼라고 함). 정렬 시 `isPinned`를 우선시키는 백엔드/프론트 로직 자체는 건드리지 않았음 — 어디까지나 시각적 뱃지/아이콘만 제거 대상.

## 동일 그룹 B — 게시물/인기글 리스트 아이템

- 유저 게시물 리스트 — 소형(리스트) 보기 (`apps/web/src/components/community/PostCard.tsx`, `viewMode === 'small'`) — 자유게시판/베타게임/라이브게임/신작게임소개 등 목록 보기 전체에서 공용으로 씀
- **홈 탭 "자유게시판" 카드 (`CommunityPage.tsx`, 2026-08-18 신설)** — "게임 공지 아래 카드 추가해서 자유게시판 글 기본 소형 카드 레이아웃으로, 한 번에 10개 보이게" 요청으로 추가, 같은 날 바로 "15개까지 나오게 하자"로 늘림. `PostCard`의 `viewMode="small"`을 그대로 재사용(다른 예외 없이 그룹 B 기본 스펙 그대로), 최신순 최대 15개(fetch `limit: 15` + `freePosts.slice(0, 15)`), 다른 소형 리스트 카드들과 동일하게 하나의 박스에 구분선으로 나열.
- 유저 게시물 리스트 — 대형 카드 보기 (`PostCard.tsx`, `viewMode === 'large'`) — 위와 같은 화면들에서 그리드/카드 보기로 전환했을 때
- 커뮤니티 홈 탭 "커뮤니티 인기글" 카드 (`CommunityPage.tsx`)
- **메인 화면(`/`, `MainPage.tsx`)의 "커뮤니티 인기글" 위젯(`HotPostsColumn` 컴포넌트)** — 2026-08-14, 사용자가 "메인에 커뮤니티 인기글이랑 홈에 커뮤니티 인기글이랑 게시글 레이아웃 동일하게 맞추고 수정될때 같이 수정해"라고 명시적으로 그룹에 편입시킴. 그 전까지는 순위 숫자+제목만 보여주는 훨씬 단순한 자체 레이아웃이었는데, 이 요청으로 `CommunityPage.tsx` 홈 탭 인기글과 완전히 동일한 마크업(순위+제목+댓글수뱃지+날짜 / 닉네임+조회수+좋아요)으로 통일함. **이제부터 이 위젯 또는 `CommunityPage.tsx` 홈 탭 인기글 카드 둘 중 하나를 수정하면 반드시 다른 쪽도 동일하게 수정한다** — 사용자가 명시적으로 "이건 여기만 다르게" 라고 하지 않는 한.

공통 구성: 제목(그룹 전체 공통 스펙) + 댓글수(`MessageSquare`, 제목 바로 옆, `text-accent font-semibold` + `bg-accent/10` 알약 배지로 강조) + 날짜 / 닉네임(그룹 전체 공통 스펙) + 조회수 + 좋아요 (2개 스탯). 채널/게임 뱃지, 공식계정/레벨 뱃지, 고정(`Star`)/핫(`Flame`) 아이콘은 전부 제거된 상태 (2026-08-13). 댓글수 자리는 공지의 "댓글 UI 없음"과 대비되는 자리 — 공지는 댓글 기능이 없어서 그 자리에 날짜가 오고, 게시물/인기글은 댓글수가 온다.

- **소형(리스트) 보기**: 1줄 = 제목+댓글수+날짜 / 2줄 = 닉네임+조회수+좋아요. 이미지가 있으면 좌측에 52x52 썸네일(없으면 자리 자체가 없음).
- **대형 카드 보기**: 위 칸 배치에 더해 상단에 큰 썸네일(동영상이면 "동영상" 뱃지), 2줄에 작성자 아바타(프로필 이미지 또는 이니셜 원형)가 추가로 붙는다 — 이건 대형 카드 고유 요소라 통일 대상 아님(2026-08-13, "대형도 구성 수정해야겠지" 요청 때 아바타/썸네일은 그대로 두고 텍스트 구성만 그룹 B 스펙에 맞춤).
- "커뮤니티 인기글"만 순위 숫자(`{i+1}`)가 추가로 붙는데, 이건 인기글 고유 요소라 통일 대상 아님.
- **"커뮤니티 인기글"은 2026-08-14에 사용자가 명시적으로 위 공통 구성과 다른 자체 스펙을 지정함** (소형/대형 리스트의 닉네임+조회수+좋아요 스펙을 따르지 않는다), **같은 날 두 번째 수정으로 최종 확정**: **1줄 = 제목만** / **2줄 = 게시글이 속한 탭 이름(`p.gameId?.title ?? CHANNEL_MAP[p.channel].label`) + 댓글수(탭 이름 바로 오른쪽)**. 날짜는 완전히 제거됨(처음엔 1줄에 제목+댓글수, 2줄에 탭이름+날짜(오른쪽 끝 정렬)이었는데 "날짜 삭제하고 댓글은 탭 이름 오른쪽으로 이동"이라고 재요청받아 정정). 닉네임/조회수/좋아요/날짜는 인기글에서 전부 빠진다 — 이건 인기글만의 예외이고, `PostCard.tsx`의 소형/대형 게시물 리스트는 기존 스펙(닉네임+조회수+좋아요) 그대로 유지한다. `MainPage.tsx`의 "커뮤니티 인기글" 위젯과 `CommunityPage.tsx` 홈 탭 인기글 카드 둘 다 이 예외 스펙으로 동일하게 맞췄다(위 항목 참고 — 이 둘은 항상 같이 수정).
- **홈 탭 "신작게임소개" 카드는 완전히 별도 레이아웃 (2026-08-14~18, 여러 번 반복 수정 끝에 최종 확정)**: 처음엔 `PostCard viewMode="large"`를 그대로 써서 한 번에 게시물 1개만 보여주고 좌우 화살표로 넘기는 방식이었음(그 과정에서 `PostCard.tsx`에 `hideStats`/`hideAuthor`/`hideDate`/`largeTitleClassName`/`onPrev`/`onNext` prop을 추가했었음). **2026-08-18에 "한 페이지에 3개씩 나오게 해"로 완전히 교체** — 이제 `PostCard`를 아예 안 쓰고 `CommunityPage.tsx`에 직접 손으로 그린 마크업으로 3개를 가로로 나란히 보여주고(`newGamePage` 상태, 페이지당 3개, 좌우 화살표로 페이지 이동), 각 미니 카드는 썸네일(`flex-1 min-h-0` + `object-cover`로 남는 세로 공간을 꽉 채움, 이미지 없으면 `Gamepad` 아이콘) + 제목(1줄, `text-[13.2px]`)만 있음 — 작성자/날짜/댓글수 등 텍스트 정보는 아예 없음. **이 교체로 `PostCard.tsx`에 추가했던 위 6개 prop은 전부 사용처가 없어져서 되돌림(원래 상태로 복원)** — 다른 화면에서 이 prop들을 다시 참고하지 말 것, 이미 지워짐.
- **높이 맞추기 (2026-08-18, "높이는 여기까지 맞추고")**: 처음엔 픽셀값 없이 순수 flexbox로 시도함 — 두 카드를 감싸는 행(`flex items-stretch`)이 더 큰 쪽 높이에 맞춰 늘려줄 거라 보고, 신작게임소개 카드 바디를 `flex-1 min-h-0` + 내부 3열 그리드도 `h-full`로 만들어서 주어진 높이를 꽉 채우게 했음. **그런데 실제로는 버그가 있었음**: 이미지 없는 게시물(플레이스홀더 아이콘만 있는 카드)이 페이지에 섞이면, `flex-1 min-h-0`를 가진 중첩 flex 요소는 확정된 높이가 없는 상태에서 "자연 높이"를 계산할 때 콘텐츠(작은 아이콘)만큼만 작게 잡혀버려서, 페이지를 넘길 때마다(3개 → 2개, 이미지 유무 조합에 따라) 전체 행 높이가 들쭉날쭉 바뀌는 문제가 있었음(2026-08-18, "한 번 페이지 넘기니깐 2개 밖에 없어서 높이가 바뀌는데"). **최종 해결**: 행 자체에 고정 높이(`h-[340px]`)를 직접 지정함 — `items-stretch`에 의존하지 않고 두 카드가 항상 이 고정값으로 렌더링되므로 콘텐츠 개수/이미지 유무와 무관하게 높이가 절대 안 바뀐다. **교훈**: "다른 콘텐츠에 맞춰 늘어나야 하는 카드"에 `flex-1 min-h-0`를 중첩시키는 순수 flexbox 스트레치 방식은 콘텐츠가 자연 높이 계산에 관여할 여지가 있으면(이미지 유무처럼 콘텐츠가 있다 없다 하는 경우) 불안정할 수 있다 — 높이를 진짜 고정하고 싶으면 그냥 명시적 픽셀 높이를 주는 게 더 안전하다.
- **너비 재조정 (2026-08-18)**: "신작게임소개 + 커뮤니티 인기글" 행의 폭 비율을 신작게임소개 60% / 인기글 42%로 바꿈(원래 42%/60%에서 서로 맞바꾼 것과 동일 — 인기글을 30% 줄인 만큼 신작게임소개로 넘김). 인기글 카드에는 `ml-auto`를 추가해서 줄어든 폭만큼 왼쪽에 빈 공간이 남지 않고 항상 행의 오른쪽 끝에 붙도록 함.
- **같은 날 인기글 폭 추가 축소**: "인기글 카드 넓이를 30% 더 줄여봐"로 42% → 29.4%(42%에서 30% 추가 축소, `42*0.7`)로 다시 줄임. 이번엔 신작게임소개 쪽을 넓히라는 말이 없어서 신작게임소개는 60%로 그대로 두고 인기글만 축소함 — `ml-auto`가 있어서 줄어든 폭만큼 신작게임소개와 인기글 사이에 빈 공간이 생기고 인기글은 계속 행의 오른쪽 끝에 붙어있다(의도된 동작).
- **바로 이어서 "신작게임소개 넓이 넓혀봐"**: 인기글을 줄이고 남은 빈 공간(약 10.6%p)을 신작게임소개로 채움 — 60% → 70.6%. 이제 신작게임소개(70.6%) + 인기글(29.4%) = 100%로 행 안에 빈 공간이 없다.

**카드 테두리 색상(틀)**: 소형뷰/대형카드 둘 다 원래 `isPinned`(보라 테두리)/`isHot`(주황 링)에 따라 카드 테두리 색이 달랐는데, 2026-08-13에 사용자가 "핫이든 뭐든 테두리 다 통일해"라고 명시적으로 요청해서 전부 기본 `border-line` 하나로 통일함 — isPinned/isHot 여부와 무관하게 테두리 색은 항상 동일하다.

## A와 B가 다른 점 (확정 — 통일 대상 아님)

그룹 A(공지)는 타입 뱃지 + 날짜 + 3번째 스탯(댓글수, 2줄에 위치)을 그대로 갖고, 그룹 B(게시물/인기글)는 이걸 전부 뺀 단순화된 구성이다. "공지 뱃지도 뺄까요?"라고 물었을 때 사용자가 "일단 배찌는 그대로두고"라고 확정함(2026-08-13) — 그룹 A의 뱃지/날짜는 그대로 유지, 더 이상 열린 질문 아님. 제목/닉네임 크기·색상만 A/B 공통으로 맞춘다.
