# 날짜 표기 통일 규칙

## 규칙

**화면에 보여주는 "단순 날짜"(시간 없이 연/월/일만)는 사이트 전체에서 항상 하나의 형식만 쓴다: `2026. 8. 14.`** (연도. 월. 일. — 월/일은 0으로 채우지 않음, 각 숫자 뒤에 마침표+공백, 마지막에도 마침표). 화면마다 `2026/08/14`, `2026.08.14`, `2026-08-14`, `2026년 8월 14일` 등 제각각 다른 형식으로 하드코딩하지 않는다 — 실제로 2026-08-14 기준 커뮤니티/관리자/파트너/서포트 화면 등 25개 이상 파일에서 최소 5가지 다른 날짜 형식이 섞여 있었음.

- 날짜 하나를 수정하면 **묻지 않고** 같은 종류의 날짜를 쓰는 나머지 전부에도 이 형식을 적용한다.
- 새로 날짜를 화면에 표시할 때, 절대 `getFullYear()`/`getMonth()`/`getDate()`를 직접 조합하거나 `toLocaleDateString()`을 옵션과 함께 호출하지 않는다 — 아래 공용 함수 하나만 쓴다.

## 공용 함수

`apps/web/src/lib/formatDate.ts`:

```ts
export function formatDate(date: string | Date): string {
  return new Date(date).toLocaleDateString('ko-KR')
}
```

사용법:

```ts
import { formatDate } from '@/lib/formatDate'

<span>{formatDate(post.createdAt)}</span>
```

null/undefined가 될 수 있는 값이면 호출하는 쪽에서 `date ? formatDate(date) : '-'` 형태로 감싼다 (공용 함수 자체는 항상 유효한 값을 받는다고 가정).

## 이 규칙이 적용되는 대상 (그룹 전체)

커뮤니티 게시글/공지/댓글 목록·상세, 관리자 각종 테이블의 "가입일/등록일/수정일/승인일/신청일/삭제일" 컬럼, 마이페이지 활동 내역, 파트너 프로젝트/지원 날짜, 결제/정산 내역의 날짜 컬럼, 미니홈/공지 발행일 등 — **시간 없이 날짜만 보여주는 곳은 전부 이 그룹**이다.

## 그룹 밖 — 통일 대상이 아닌 예외 (2026-08-14 확인)

아래는 "날짜"처럼 보이지만 실제로는 다른 목적을 가진 표시라서 이 규칙을 적용하지 않는다. 새로 비슷한 걸 만들 때도 아래 기준으로 판단한다.

1. **날짜+시간이 한 문자열로 결합된 표시** (예: "8월 14일 15:30", `hour`/`minute` 옵션이 들어간 `toLocaleDateString`) — 시간 부분까지 있는 타임스탬프는 이 규칙 대상이 아니다. 발견된 곳: `PlayerMyPage.tsx`(2곳), `PlayerGameDetailPage.tsx`, `FeedbackManagementPage.tsx`(2곳). 나중에 이 시간 포함 표시들도 통일하고 싶다면 별도로 논의해서 결정한다 — 이 라운드에서는 건드리지 않음.
2. **상대 시간** (`getRelativeTime` — "3일 전", "방금 전") — 날짜 문자열이 아니라 상대적 경과 시간이라 대상 아님. 다만 `apps/web/src/lib/relativeTime.ts`의 7일 이상 지난 폴백은 이미 `toLocaleDateString('ko-KR')`(이 규칙과 동일한 결과)를 쓰고 있어서 그대로 둠.
3. **"오늘" 날짜 + 요일 헤더** (`AdminDashboardPage.tsx`, 예: "2026년 8월 14일 목요일") — 대시보드 인사말/헤더용 완전한 문장형 날짜라 목적 자체가 다름. 통일 대상 아님.
4. **월/일만 보여주는 좁은 마감 배지** (`PartnerMatchingProjectsPage.tsx`, `partner-profile/PostsSection.tsx` — "8/14" 형태 마감 카운트다운 칩) — 연도 없이 공간을 아끼려는 의도적 디자인. 통일 대상 아님.
5. **좁은 관리자 테이블 컬럼의 2자리 연도 압축 표기** (`AdminGamesPage.tsx`의 베타/라이브 시작~종료일, 커스텀 정규식으로 "26.08.14" 형태로 만듦) — 좁은 컬럼 폭에 맞춘 의도적 압축 표기. 통일 대상 아님.
6. **월 단위 정산 기간** (`AdminSettlementsPage.tsx`의 `toYearMonth`/`fmtYM` — "2026-08" 내부 키, "2026. 08." 표시) — 날짜가 아니라 "월" 단위 버킷이라 일/day 개념 자체가 없음. 통일 대상 아님.
7. **차트 X축/툴팁의 압축 라벨** (`VipUsersChart.tsx`의 `M/D` 형태) — 차트 공간 제약상 압축 표기가 필요한 디자인 요소. 단, 같은 파일의 테이블 "날짜" 컬럼(`h.date`)은 이 규칙 대상이라 이미 `formatDate`로 통일함 — 압축 축 라벨과 테이블 날짜 컬럼은 서로 다른 취급.
8. **`<input type="date">` 등 폼 입력값** — ISO `YYYY-MM-DD`가 필요한 자리라 표시용 포맷과 무관. 대상 아님.
9. **백엔드(`apps/api`) 응답의 날짜 포맷** — API는 항상 원본 ISO 문자열을 내려주고, 화면에 보여줄 때 프론트엔드가 포맷한다. 백엔드에서 날짜를 미리 포맷해서 내려주지 않는다.

## 새 화면을 추가할 때

- 시간 없는 순수 날짜를 보여줘야 하면 무조건 `import { formatDate } from '@/lib/formatDate'`부터 쓴다. 직접 `getFullYear()`를 조합하거나 `toLocaleDateString()`을 옵션과 함께 호출하지 않는다.
- 위 "그룹 밖 예외" 중 하나에 해당한다고 판단되면(날짜+시간 결합, 압축 배지/칩, 차트 축 라벨 등) 그 이유를 코드 주석 없이도 알 수 있게 화면 성격상 명확히 구분되게 만들고, 애매하면 이 문서의 예외 목록에 사례를 추가한다.
