# 커뮤니티 사이드바 카테고리 탭 강조/펼침 규칙

## 규칙

커뮤니티 사이드바 카테고리 목록(`apps/web/src/components/pages/CommunityPage.tsx`의 `CATEGORIES`)에 속한 모든 탭은 강조(하이라이트)·하위 탭 펼침/접힘에 대해 **동일한 규칙**을 따른다. 새 탭을 추가하거나 기존 탭의 동작을 바꿀 때, 사용자가 명시적으로 다르게 하라고 하지 않는 한 아래 규칙을 그대로 적용하고, 탭별로 따로 분기 로직을 만들지 않는다.

### 강조(활성화) 규칙

데스크톱/모바일 사이드바 둘 다 공통 함수 `isCategoryActive(cat, channel, search, selectedGame)` 하나만 사용한다 (각 화면에 따로 로직을 두지 않는다).

1. **홈**: `channel`/`search`/`selectedGame`이 전부 없을 때만 강조
2. **하위 탭(`subTabs`)이 있는 카테고리** (예: 공지사항 → 게임업 공지/게임 공지): `channel`이 하위 탭 중 하나와 일치하면 부모도 강조
3. **하위 게임 목록이 있는 카테고리** (베타게임/라이브게임): `channel`이 일치하거나, 지금 선택된 게임(`selectedGame`)이 그 서비스타입(beta/live)에 속하면 강조 — 다른 화면(게시글의 게임 뱃지 클릭 등)에서 곧바로 게임으로 진입해도 부모 탭이 강조되어야 함
4. **그 외 하위 탭 없는 카테고리** (신작게임소개/자유게시판/즐겨찾기): `channel`이 일치할 때만 강조

### 게임 선택은 항상 그 게임이 속한 채널로 전환한다

`handleGameClick`으로 게임을 선택하면(사이드바 게임 목록이든, 게시글의 게임 뱃지든, 공지 목록의 게임 이름이든 — 어디서 클릭했는지 무관) **그 게임의 서비스타입(beta/live)에 맞는 채널로 `channel`도 같이 바뀐다.** 게임만 선택되고 `channel`은 이전 탭에 머물러 있는 상태(사이드바는 게임이 선택된 것처럼 보이는데 본문은 여전히 이전 탭 내용을 보여주는 것)를 만들지 않는다 — 사이드바 강조/본문 콘텐츠는 항상 같은 상태를 봐야 한다.

### 펼침/접힘 규칙

- 하위 항목(정적 `subTabs` 또는 동적 게임 목록)이 있는 카테고리만 접기/펼치기 화살표(chevron)를 가진다.
- 기본 상태는 전부 접힘(`DEFAULT_COLLAPSED_CATS`) — 처음 들어왔을 때 하위 목록은 보이지 않는다.
- 화살표 클릭(`toggleCollapse`)은 **그 카테고리만** 토글한다 (다른 카테고리 상태에는 영향 없음).
- **카테고리 이름(라벨) 클릭은 "그 카테고리의 첫 번째 하위 항목을 바로 선택"하는 것과 같다** (`handleCategoryLabelClick`, 공지사항/베타게임/라이브게임 전부 동일 함수 하나로 처리). 부모 카테고리 자체의 "전체 보기" 화면을 거치지 않고, 곧바로 첫 자녀의 화면이 펼쳐진 채로 나온다.
  - 하위 탭(`subTabs`)이 있으면 → 첫 번째 하위 탭 선택 (`handleSubTabClick`)
  - 하위 게임 목록이 있으면 → 목록의 첫 번째 게임 선택 (`handleGameClick`)
  - 둘 다 없으면(자유게시판/즐겨찾기 등) → 그 카테고리 자체로 이동 (`handleCategoryClick`)
  - **단, 하위 항목이 있는 카테고리가 이미 펼쳐진 상태(`!isCollapsed`)에서 라벨을 한 번 더 누르면, 위 선택 동작 대신 그냥 접기만 한다** (`toggleCollapse`) — 아코디언처럼 라벨 클릭이 "열기(+첫 항목 선택)"와 "닫기" 토글로 동작한다.
- **클릭 종류에 따라 정해진 핸들러만 쓰고, 탭마다 새 로직을 만들지 않는다:**
  1. **"하위 항목(게임 하나, 또는 공지사항의 하위 탭 하나)을 직접 선택"** → `handleGameClick` / `handleSubTabClick`. 이 항목들은 부모가 이미 펼쳐져 있어야만 화면에 보이고 클릭할 수 있으므로, 두 핸들러 모두 **펼침 상태를 아예 건드리지 않는다** — 건드릴 필요가 없다(이미 펼쳐진 채로 유지됨). 여기서 펼침 상태를 계산해서 다시 `setCollapsedCats`를 호출하면(설령 결과가 옳더라도) 리렌더 사이에 한 번 접혔다가 펴지는 깜빡임이 생기므로 **절대 하지 않는다.**
  2. **"카테고리 이름(라벨) 클릭"** (또는 즐겨찾기처럼 하위 항목이 없는 카테고리 클릭) → `handleCategoryClick`. 채널을 이동시키면서 **최종 펼침 상태를 그 자리에서 한 번에 계산**한다(`collapsedStateForCategoryNav`): 기본은 전부 접힘이지만, 이동하려는 값이 어떤 카테고리의 하위 탭이라면 그 카테고리는 편 상태로 계산해 넣는다. **먼저 접었다가 나중에 이펙트로 다시 펴는 2단계 방식은 금지** — 반드시 클릭 시점에 최종 상태를 한 번에 반영해서 깜빡임이 생기지 않게 한다. (`handleCategoryLabelClick`이 실제로는 위 1번의 `handleGameClick`/`handleSubTabClick`으로 위임하는 경우가 많아, 이 2단계 계산은 하위 항목이 없는 카테고리로 이동할 때만 의미가 있다.)
- 첫 렌더링(서버 사이드 렌더링 포함) 시점의 펼침 상태도 `initialCollapsedCats()`로 URL 상태(channel/selectedGame)에 맞게 미리 계산한다 — 그렇지 않으면 딥링크/새로고침으로 들어왔을 때 "전부 접힘"으로 그려졌다가 클라이언트에서야 펼쳐지는 깜빡임이 생긴다.
- **딥링크/새로고침/뒤로가기처럼 클릭을 거치지 않고 URL이 바로 바뀌는 경우**를 위한 안전망으로, `useEffect`가 "지금 선택된 값"(`selectedGame`, `channel`)을 감지해서 해당 카테고리만 펼친다. 클릭 경로에서는 위 핸들러들과 초기 상태 계산이 이미 정확한 최종 상태를 반영하므로 이 이펙트는 그저 같은 값을 다시 확인하는 것뿐이라 깜빡임을 만들지 않는다.
  - 베타게임/라이브게임: `selectedGame`이 그 서비스타입에 속하면 펼침 (`selectedGame?.id` 감지)
  - 공지사항 등 `subTabs`가 있는 카테고리: `channel`이 그 하위 탭 중 하나와 일치하면 펼침 (`channel` 감지)
  - 다른 카테고리의 펼침 상태에는 영향 없음(그대로 유지).

## 새 탭을 추가할 때

- `CATEGORIES` 배열에 항목을 추가한다.
- 하위 항목이 필요하면 정적 목록은 `subTabs`(→ 항목 클릭은 `handleSubTabClick` 재사용), 동적 목록(게임 등)은 베타게임/라이브게임과 같은 방식(→ `handleGameClick` 재사용)을 그대로 쓴다. 새로운 강조/펼침 규칙이나 새 클릭 핸들러를 따로 만들지 않는다.
- `isCategoryActive()`, `DEFAULT_COLLAPSED_CATS`, `collapsedStateForCategoryNav()`, `initialCollapsedCats()`, `handleCategoryLabelClick()`을 새 탭에 맞게 확장한다 (새 함수를 만들지 않는다).
