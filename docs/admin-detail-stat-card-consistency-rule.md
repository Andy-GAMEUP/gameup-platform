# 관리자 상세정보 화면 내부 통계 카드 테두리 통일 규칙

## 규칙

관리자 상세정보류 화면 안에서, 카드(`bg-bg-secondary border border-line`) 내부에 다시 작은 통계/데이터 타일(`bg-bg-tertiary/50 rounded-xl p-4`)을 넣는 경우, 이 내부 타일의 테두리는 항상 `border border-line`을 그대로 써서 바깥 카드 테두리와 색을 통일한다 — 타일마다 다른 색/두께의 테두리를 임의로 넣지 않는다.

- 내부 타일 테두리 하나를 수정하면, 사용자가 "이건 이쪽만 다르게 해줘"라고 명시적으로 지정하지 않는 한 **묻지 않고 같은 그룹의 나머지 화면 전부에도 동일하게 적용**한다
- 새로 이런 형태의 상세정보 화면을 추가하면 이 문서의 목록도 함께 업데이트한다

## 수정/조회 불가 필드는 입력창(Field+Input disabled) 형태로

- 가입일, 최근 로그인, 레벨처럼 **관리자가 수정할 수 없는 단순 조회용 필드**는 통계 타일이 아니라, 아이디/이메일과 같은 `Field` + `Input(disabled)` 행 형태로 넣는다 (동일 화면 안에서 라벨/입력창 스타일 통일)
- 활동점수/캡코인처럼 **수정 가능(연필 아이콘 → 편집 팝업)한 필드만** 통계 타일(`bg-bg-tertiary/50 border border-line rounded-xl p-4`) 형태를 쓴다

## 좌우 2단 레이아웃 구성 시 주의 (2026-09-07)

이 화면은 `grid grid-cols-[1fr_고정폭]` 바깥 그리드 안에, **왼쪽은 `space-y-6`으로 감싼 별도 컨테이너**(계정/기업 정보, 관리자 권한 정보, 커뮤니티 게시글 등 폭이 같아야 하는 카드들을 전부 그 안에 세로로 쌓음), **오른쪽은 관리자 메모 하나만** 두는 중첩 구조를 쓴다.

- 카드를 조건부(`viewType === '...' &&`)로 껐다 켰다 하는 화면에서 모든 카드를 그냥 그리드의 직계 자식으로 나열하면, 카드 개수 홀짝에 따라 CSS grid 자동배치가 카드를 엉뚱한 칸(관리자메모 옆 좁은 칸)에 밀어넣는 버그가 생긴다 — 새로 카드를 추가/삭제할 때 폭이 안 맞으면 이 문제부터 의심할 것
- "왼쪽 폭에 맞춰야 하는" 카드를 추가하면 반드시 왼쪽 `space-y-6` 컨테이너 안에 넣는다 (그리드의 직계 자식으로 추가하지 않는다)

## 현재 적용 대상

- `apps/web/src/components/pages/AdminUserDetailPage.tsx` — 계정 정보 카드 (2026-09-04~07)
  - 조회 전용(Field+Input disabled): 아이디, 이메일, 레벨, 가입일, 최근 로그인, 관심 장르(콤마 텍스트), 자기소개
  - 수정 가능(통계 타일): 활동점수, 캡코인 (적용 미정)
  - 계정 상태(정상/정지 배지 + 계정 중지·해제 버튼)는 카드 안이 아니라 화면 맨 아래 뒤로가기/저장 버튼과 같은 줄, 왼쪽에 배치
